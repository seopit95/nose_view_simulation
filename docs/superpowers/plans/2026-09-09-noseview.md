# NoseView 0.1 개발 계획

> 0.1 시제품 개발이 완료된 과거 계획이다. 다음 작업을 자동으로 지시하지 않는다. 현재 범위·검증·진행 상태는 [AGENTS.md](../../../AGENTS.md)와 [현재 상태](../../harness/status.md)를 먼저 확인한다.

승인 근거: 사용자의 “일반 사제 웹캠…그렇게 개발 진행해줘”와 앞서 합의한 Electron / React / TypeScript / MediaPipe / Three.js 설계. 새 프로젝트에 개발하며 기존 파일은 변경하지 않는다.

## 목표와 범위
Windows/macOS 공통 소스로 일반 UVC 웹캠을 연결하고, 추적된 얼굴의 코 영역을 제한적으로 변형해 원본과 비교하는 실행 가능한 상담 시제품. 이번 호스트에서는 macOS arm64 패키지를 실제 실행 검증한다. Windows 하드웨어 검증은 별도다.

범위: 카메라 선택·종료·권한/장치 오류, 합성 인물 예시, 단일 얼굴/자세 품질 조건, 상대 단위의 코 폭·콧대 윤곽·코끝 위치, 원본/분할 비교, 일시정지, A/B/C 임시안, 초기화, 명시적 동의 후 안내 문구가 포함된 PNG 저장. 기록 DB·로그인·클라우드·수술 결과 예측·mm 계측·상용 인증은 포함하지 않는다.

## 구조와 제약
- React UI → 프레임 파이프라인 → MediaPipe Worker → 동일 프레임과 랜드마크 → Three.js 국소 역방향 UV 변형.
- 최대 한 프레임만 처리 중. 다음 처리 시 최신 영상 프레임을 취득한다. 이전 소스 결과는 세대 번호로 폐기한다.
- 추적 실패·복수 얼굴·큰 자세 변화에는 변형을 끈다. 품질 조건은 보수적인 시제품 기준이며 임상 정확도 보증이 아니다.
- 카메라 접근은 버튼 클릭 후에만. 종료·세션 변경·장치 끊김 때 미디어 트랙과 프레임 자원을 정리한다.
- 모델/WASM/예시는 앱에 포함. 앱 런타임 외부 네트워크 차단. 환자 정보/영상 자동 저장 없음. 진단 로그에 사진을 쓰지 않는다.
- Electron 격리·샌드박스·좁은 저장 IPC. macOS 카메라 사용 사유, Windows 공통 API, 별도 OS별 패키징.

## 패키징 결정
Electron Forge 7의 기본 archive 의존성에서 npm audit 취약점이 확인되었고, 최신 Packager 20으로 강제 교체하면 Forge의 callback hook API가 호환되지 않았다. 실제 실패 로그로 확인 후 Forge 계층을 제거하고 @electron/packager 20.3.0을 직접 사용한다. 앱의 Electron/React/MediaPipe 구조는 같다. ZIP은 운영체제 기본 도구를 사용한다.
