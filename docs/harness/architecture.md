# 설계와 불변 조건

이 문서는 현재 구현을 설명하고 변경 시 지킬 계약을 지정한다. **계약의 존재가 모든 경로의 검증 완료를 뜻하지는 않는다.** 시험 범위와 빈틈은 [quality.md](quality.md), [status.md](status.md)를 따른다.

## 실행 구조

```text
App: 입력 장치 / 상담 상태 / 사용자 동작
  └─ Pipeline: 프레임 취득 + FrameGate의 ticket
      └─ classic Worker: 같은 bitmap의 축소 복사본 → MediaPipe Face Landmarker
          └─ 같은 bitmap + ticket + 얼굴 좌표 + 변환 행렬
      └─ evaluateFace: 같은 결과의 상담/필터 품질 판정 + 코 영역
  └─ Viewport: 원본 프레임 + 국소 GPU 변형 + 양쪽 동일 촬영 보정 + 비교
      └─ ExportDialog: 미리보기 + 동의
          └─ preload의 savePng → Electron main의 검증/저장
```

| 소유 파일 | 책임 | 경계 |
|---|---|---|

| [pipeline.ts](../../src/tracking/pipeline.ts) | 프레임 취득·전달·결과 수락·시간 초과·Worker 종료 | 환자/저장 UI를 모른다. |

| [preload.cjs](../../desktop/preload.cjs) / [main.cjs](../../desktop/main.cjs) | 좁은 bridge / origin·권한·PNG 저장 | renderer 입력을 신뢰하지 않는다. |

`core`는 가장 안쪽 순수 계층이다. tracking은 core를 사용하고, UI가 tracking과 Viewport를 연결한다. Viewport의 `TrackedFrame` 사용은 타입 의존이다. renderer에서 Electron main을 직접 import하지 않는다. 지금 필요하지 않은 계층·범용 버스·플러그인 엔진·상태관리 라이브러리를 추가하지 않는다.

## 변경 후에도 유지할 계약

| ID | 불변 조건 | 주요 검증 |
|---|---|---|
| INV-01 | 추론한 bitmap과 그 결과만 묶어 표시한다. 최신 영상에 과거 랜드마크를 붙이지 않는다. | pipeline 단위 시험 + 움직이는 영상 통합 시험 |
| INV-02 | 처리 중 프레임은 최대 1개다. `invalidate()`는 세대만 바꾸며 처리 소유권을 풀지 않는다. | frame-gate 단위 시험 |
| INV-03 | 입력 변경·일시정지·종료 뒤 낡은 ticket의 결과는 표시하지 않는다. 중복 응답도 현재 잠금을 풀지 않는다. | frame-gate / pipeline 시험, 수명 전환 E2E |
| INV-04 | 해당 모드의 품질 불량에는 `frame: null`, 변형 비활성, 조절·저장 불가로 일관되게 동작한다. 오래된 유효 코 좌표를 쓰지 않는다. | geometry + 실제 모델 E2E |
| INV-05 | 코 조절값 0은 같은 촬영 보정의 원본과 일치하고, 코 변형 영역 밖은 동일 보정의 원본을 보존한다. 비보정 픽셀 비교는 보정 없음에서 수행한다. CPU 참조식과 GPU 변형식의 의미가 일치한다. | geometry + GPU 픽셀 비교 |
| INV-06 | 입력 전환·연결 해제·새 상담은 영상·A/B/C·저장 미리보기를 비우고 촬영 보정은 저장 기본값, 코는 자동 적용 선택 시 저장 프리셋/그 외 0으로 복원한다. 실시간 필터 안에서 첫 연결/장치 변경 시에만 명시적으로 고정한 숫자를 유지한다. 필터 탭 이동은 입력 변경이 아니며 연결과 정지 프레임을 유지한다. 이전 상담의 임시 값을 재사용하지 않는다. 새 비동기 작업이 이전 작업에 의해 취소되지 않는다. | 연결 취소·분리·새 상담/설정 E2E |
| INV-07 | 소유한 자원은 사용 종료 시 해제한다. 늦은 stream/bitmap도 정리한다. | 단위/E2E + 실물 반복/장시간 시험 |
| INV-08 | WebGL/Worker의 치명적 실패 후 늦은 ready/결과가 정상 화면을 되살리지 않는다. | 시작 실패 E2E, 관련 장애 주입 |
| INV-09 | 화면과 PNG에서 원본/가상, 거울 방향, 코 조절값, 촬영 보정값, 안내가 일치한다. 보정 적용 원본을 비보정으로 표시하지 않는다. | UI/저장 통합 시험 + 시각 확인 |
| INV-10 | 전역 톤은 얼굴 유무·정면 조건과 독립이다. 피부 질감은 현재 프레임의 단일 얼굴에서 검증한 기하로만 적용한다. 얼굴 안쪽 타원(이마·볼·턱)에 한정하고 코·눈·눈썹·입술을 제외한다. 양쪽/PNG에 동일 보정, 추적 입력은 비보정이다. 상담의 코 변형/저장 조건을 톤 보정 때문에 완화하지 않는다. 실시간 필터의 별도 자세 조건은 아래 계약을 따른다. | beauty/pipeline 단위 + 실제 GPU/모델 보정/설정 E2E |

참조용 `inverseWarp()`만 수정하고 실제 GLSL을 놓치지 않는다. 셰이더만 수정하고 단위 시험이 검증한다고 생각하지 않는다. 타원 밖 보존과 0 설정 동등성은 GPU 통합 결과로도 확인한다.

## 상태 전환 계약

현재 App은 단일 상태 머신 라이브러리 대신 state/ref를 사용한다. 아래 표는 **행동 계약**이며 기존 코드에 없는 enum이 구현돼 있다고 간주하지 않는다.

| 사건 | 기대 결과 |
|---|---|
| 시작 | 저장된 기본값 복원 후 빈 카메라 연결 대기. 예시 로딩/getUserMedia 호출 없음. 손상/접근 실패는 공장값과 설정 확인 안내. |
| 연결 요청 | 이전 입력·A/B/C·미리보기 정리, 작업 번호 증가, 연결 중 표시. 필터는 고정 숫자 유지, 상담은 기본 수치 복원. |
| 연결 중 취소/다른 입력 | 작업 번호 무효화. 뒤늦게 받은 스트림 종료. 이전 작업 오류가 새 입력을 중단하지 않음. |
| 첫 영상 재생 시간 초과 | stream 취득 후8초 내 video.play 완료가 없으면 TimeoutError로 구분해 트랙 종료/off 복귀. USB/다른 앱 확인과 재연결 안내. 연결 중에는 첫 영상 대기 안내를 표시하며 다시 연결하라는 문구를 표시하지 않음. 성공/실패 후 재생 대기 타이머 해제. |
| 얼굴 없음/복수/자세 불량 | 현재 프레임의 원본 + 전역 톤 + 안내. 코 조절·저장 비활성, 촬영 보정 조절은 가능. 단일 얼굴 기하가 유효하면 질감도 적용. |

| track ended / 연결 해제 | 트랙·이벤트·영상·설정 정리, off 상태, 필요 시 재연결 안내. |

| 치명적 오류 | 트랙 중단, Pipeline 종료, 표시·저장 미리보기·임시 설정 비우기, 오류 유지, 앱 다시 불러오기 안내. 새 상담으로 오류 안내를 지우지 않음. |
| 저장 창 열기 | 상담 모드에서만 유효한 프레임을 캡처, 카메라 처리는 일시정지. 저장 동의는 새 창마다 초기화. |

위 상태 경합은 `tests/lifecycle.mjs`의 실제 모델/가상 카메라 시험으로 확인한다. 연결 완료 시에도 화면 숨김 여부를 확인한다. 정상 mute 복구는 자동 추적을 재개하되, 이미 일시정지를 요청했다면 재생 동작까지 기다린다.

## 자원 소유권과 좌표

- App: MediaStream/video, 장치·트랙·문서 이벤트. 취소 후 도착한 스트림도 종료 책임이 있다.
- Pipeline: Worker, animation callback, timeout, FrameGate. 소스를 무효화해도 이전 작업의 소유권은 응답까지 남을 수 있다.
- bitmap: 취득 → Worker에 transfer → 결과를 UI에 transfer → Viewport가 캔버스 복사 후 `close()`. 폐기 경로는 Pipeline/수신자가 닫는다. 전송 성공 후 송신자가 다시 사용하지 않는다.
- Worker의 축소 추론 캔버스는 동기 추론 성공/실패 뒤 finally에서 픽셀을 비운다. 같은 원본 bitmap을 반환하며 다음 video 프레임에서 별도 추적 입력을 얻지 않는다.
- Viewport: texture/material/geometry/WebGLRenderer, context 이벤트, ResizeObserver. 해제·언마운트·그래픽 실패를 함께 점검한다.
- 텍스처는 처음 사용하는 프레임에서 만들고 같은 크기의 후속 프레임에 재사용한다. 가로/세로 중 하나라도 바뀌면 기존 GPU 텍스처를 dispose하고 새 CanvasTexture로 교체하며 셰이더 uniform도 갱신한다. input 캔버스 크기 변경과 needsUpdate만으로 GPU 저장 크기가 바뀐다고 가정하지 않는다. clear에서는 텍스처와 uniform 참조를 해제하고 원본 캔버스도 비운다.
- 모델 정규화 좌표 → 표시 bitmap의 픽셀 좌표 → 코 로컬 축 → UV 역방향 샘플링 순서를 유지한다. 크기 품질 조건만 추론 해상도로 환산한다.
- 거울 보기는 화면 샘플링 단계에서 처리한다. 랜드마크와 영상 중 하나만 반전하거나 이중 반전하지 않는다.
- 가이드 원본 좌표를 보관하고 현재 거울 상태로 표시한다. 정지 프레임에서 거울 상태만 바꿔도 가이드 위치·각도가 함께 갱신돼야 한다.
- 제한 시간은 해당 작업이 소유한다. 중복/낡은 응답은 다른 프레임의 제한 시간을 해제할 수 없고, 종료 뒤 ready 콜백은 무시한다. Worker 전송 실패 시 아직 소유한 bitmap을 닫는다.
- 브라우저 CSS 표시 크기와 추론 해상도를 혼용하지 않는다. 영상 종횡비·회전·거울·비교 경계 조합을 확인한다.

현재 Worker는 WASM 로더의 `importScripts` 사용 때문에 classic/IIFE로 빌드한다. [vite.worker.config.ts](../../vite.worker.config.ts)를 확인하지 않고 module Worker로 바꾸지 않는다.

## 촬영 보정과 저장

보정은 기존 shader에서 수행한다. 현재 프레임의 이마10/턱152/좌우234·454 랜드마크로 얼굴 외곽 안쪽 타원을 만들고 눈 축으로 회전한다. 반경은 좌우 폭의 .46, 이마~턱 길이의 .475이며 제곱 거리 .72~1에서 부드럽게 전환한다. 눈·눈썹·입술의 보호 타원은 경계점 범위를 모두 포함하고 외곽에서 부드럽게 전환한다. 코 변형 타원도 별도로 제외한다. 얼굴 외곽점 누락/비유한 좌표/상하·좌우 역전이면 피부 마스크를 만들지 않는다. 기하 마스크이므로 머리카락·가림을 정밀 분할한다고 설명하지 않는다.

피부 영역에서만 5×5 bilateral 샘플로 질감을 완화한다. 강도(정규화 0~1)에 따라 샘플 간격을 코 폭의 .04~.12(최종 1~12px), 색 차이 항 분모 .012~.05, 혼합량은 피부 마스크×강도×.95로 적용한다. 샘플 수는 25로 유지한다.

밝기/색온도는 검정/흰색 끝점을 유지하는 `gain*color/(1+(gain-1)*color)`로 적용한다. RGB gain은 `exp2(밝기/100*2.5 + 색온도/100*[.75,0,-.75])`다. 코 변형 후의 원본 좌표로 샘플링하며 원본/가상에 같은 함수와 값을 사용한다. 밝기·색온도 0에서는 곡선 계산을 건너뛰어 off 픽셀을 보존한다. 밝기·색온도 변화와 피부의 흐림 제외를 혼동하지 않는다.

0.3부터 위 gain 지수에 색조/100×[.35,-.35,.35]를 더한다. 톤 순서는 밝기/색온도/색조 → 그림자/하이라이트 → 대비 → 채도다. c를 [0,1]로 제한한 뒤 그림자 s·하이라이트 h(정규화 -1~1)는 `c + .8*s*c*(1-c)^2 + .8*h*c^2*(1-c)`로 적용한다. 도함수 최솟값 .2와 끝점 0/1을 보존해 조합 끝값의 밝기 역전을 막는다. 대비는 `p=exp2(대비/100*.8)`, `c^p/[c^p+(1-c)^p*(.18/.82)^(p-1)]`, 채도는 선형 휘도 [.2126,.7152,.0722]와 원색을 `1+채도/100`으로 혼합하고 최종 clamp한다. rational 곡선의 GPU 반올림으로 흰색이 1을 미세하게 넘을 수 있으므로 비정수 pow 입력을 먼저 clamp해야 한다. 각 보정 0은 해당 단계를 건너뛴다.

기본 설정은 `preferences.ts`에서 최대32768자 JSON을 읽는다. 저장 키 `noseview.preferences.v1`은 유지하고 schema 버전3에 `nosePresets[{id,name,adjustments}]`, `defaultNoseId`, `beauty`, `autoNose`를 기록한다. 버전1은 단일 ‘이효리 코 타입’으로, 버전2는 기존 타입 목록 그대로 읽는다. 기존 코3개·촬영8개·이름/ID/기본 대상·자동 여부를 보존하며 `projection=-bridge`, 나머지 새4필드0으로 이전한다. 명시적 저장 전 디스크를 바꾸지 않는다. 버전3은 코8필드 전부 유한한 숫자여야 한다. 타입1~50개, 이름1~32자(UTF-16 길이, trim, 제어문자 금지), ID1~64자 영숫자/밑줄/하이픈이다. NFKC/소문자 비교로 이름 중복을 막고 ID 중복·없는 기본 ID도 거부한다. 알 수 없는 버전·누락/비정상 숫자·타입 오류는 기본값과 안내로 복구한다.

직렬화 허용 필드만 저장하고 setItem 성공 후에만 메모리 기본값을 갱신한다. 타입은 안정적인 ID로 선택하며 이름은 React 텍스트로 표시한다. 설정창의 추가·이름·수치 편집·취소는 현재 상담을 바꾸지 않는다. 편집 대상과 기본 대상은 독립적이며 정면 조건을 만족한 상담에서 타입을 선택하거나 적용 버튼으로 수치를 반영한다. 입력 변경·새 상담은 저장 기본 ID를 선택하고 자동 적용 여부에 따라 기본 수치 또는0을 복원한다. A/B/C는 계속 임시 메모리다.

PNG는 각 뷰를 같은 크기의 임시 캔버스 원점에서 먼저 축소하고 비교 시트에 복사한다. 서로 다른 배치 좌표에서 직접 축소하면 분수 배율의 색 반올림이 달라질 수 있으므로, 0변형 양쪽 픽셀 동등성을 저장에서도 검사한다. 시트 높이는 영상 높이+240px이며 영상 원점y60은 유지한다.8개 코 수치는4개씩 두 줄, 촬영 보정은 다음 줄에 표시한다. 보정값과 동의는 내보내기 창에서도 확인한다.

## 부위별 코 조절

`Adjustments`는 `width, bridge, projection, tip, tipSize, alarLift, nostrilExposure, columella`다. `NOSE_CONTROLS`가 표시명·설정창4그룹·설명·방향과 상담 기본4개 여부(basic)를 소유한다. 설정/필터/PNG도 같은 메타데이터를 사용한다. 양수는 width/bridge/tipSize 확대, projection 바깥, tip/alarLift/nostrilExposure/columella 위다. 비공 내리기는 음수로 윗선을 내린다. 기존 key/숫자/schema3는 유지하며 노출 면적이나 수술법 자체를 나타내지 않는다. 수치는 상대 단위이며 수술량이 아니다.

현재 프레임의0/1/2/4/64/79/294/309 좌표를 검증해6개 국소 영역을 만든다. tip은4/1의 중간, alar는64/294, nostrils는79/309, columella는2, lip은0이다. 정밀 픽셀 분할이 아니다. 좌표 유한성·화면 범위·국소 범위·상하 순서·입술 간격과 보이는 쪽의 alar→nostril→tip 간격을 검사한다. 보이는 쪽 최소간격.04, 정면은 양측 검사. 가려지는 쪽은 간격.08~0과 측면 강도에 따라 연속 감쇠한다. 투영에서 숨은 쪽이 겹쳤다는 이유로 코 전체를 특정 각도에서 껐다 켜지 않는다. 한 점에 붕괴한 좌표도 정상 부위로 취급하지 않는다.

반경은 tip(.32,.20), alar(.26,.22), nostril(.22,.13), columella(.16,min(.14,입술간격×.5))의 코 정규 좌표 단위다. compact weight는 `max(0,1−타원거리²)^3 × 가시성`이다. 기본 콧대/코끝 상하 → 코끝 크기 → 좌우 콧볼 폭/콧날개 상하 → 좌우 콧구멍 윗선 → 비주 순서로 합성한다. 크기 계수.30, 부위 이동은 해당 반경×.28로 제한한다. 콧구멍 윗선은 기준점 아래에서 `1−smoothstep(0,반경y×.75,q.y−중심y)`로 연속 감쇠해 구멍 아래까지 통째로 이동시키지 않는다. 이는 기하 경계 보호이며 정밀 콧구멍 분할이 아니다. 전체 합성 변위는 코 외곽과 입술 위에서 부드럽게0이 된다. 입술 전이는 lipY−.44~lipY−.04의.40폭을 사용한다. 좁은 전이에서는 최대 효과가 겹칠 때 좌표가 접히므로 짧은 입술 간격과 혼합 부호 끝값을 함께 검사한다. CPU/GPU 식과 상수는 같이 바꾼다.

부위가 있으면 콧볼 폭을 양쪽 alar 국소 영역에 적용한다. 세부 기하를 만들 수 없으면 기존 넓은 콧볼/콧대/코끝/측면 기본 변형만 가능하며 새 세부4필드는 shader와 상담 UI에서 차단한다. 저장한 숫자는 유지하고 현재 프레임이 다시 유효해지면 복구한다. 전체 얼굴 판정 실패는 기존 INV-04대로 전체 코를 차단한다. 기본값 이전은 숫자와 이전 측면 효과의 연결을 보존하며0.7과 동일 픽셀을 보장하지 않는다.

## 실시간 필터 탭

App은 필터 진입 때 코8개/촬영8개 값과 선택한 코 타입 ID를 복사한다. 탭 이동으로 Viewport·Pipeline·stream을 새로 만들거나 일시정지를 바꾸지 않는다. 필터에는 조절/비교선/원본 누르기/PNG를 제공하지 않으며 보정 변경으로 상담에 돌아가 조절한다. 기존 보기 모드·분할 위치는 복귀 시 유지한다. 필터 고정값은 설정 저장소에 자동 기록하지 않는다.

한 Worker 결과의 같은 bitmap에 대해 두 Quality를 계산한다. 상담은20° 조건을 유지하고 필터는 표의 별도 자세/크기 조건을 사용한다. Viewport는 두 결과를 보관해 정지 중 탭 이동에도 해당 모드의 코 프레임으로 즉시 그린다. 0.7부터 yaw는 강도를 줄이지 않는다. 감쇠 t는 pitch/roll 초과량의 최대를0~1로 제한하고 강도는1−t²(3−2t)다. 코8개 값에만 곱한다. 불량에서 frame:null이며 예전 얼굴 좌표를 새 영상에 재사용하지 않는다.

좌우20~65°의 smoothstep으로 정면 눈 축/코 폭에서 코 세로축/깊이를 포함한 폭으로 전환한다. 깊이 좌표는 x와 같은 width 단위를 사용한다. 코끝을 포함하도록 중심과 폭을 조정하기 전에 독립적인 얼굴/코 크기로 이상치를 차단한다. 자기 자신으로 확대한 폭을 기준으로 코끝을 정규화하는 검사만으로는 이상치를 막을 수 없다. 합성 좌표 시험은0폭·극소폭·화면 안쪽 코끝 이상치도 포함한다.

콧대 폭과 옆모습 콧대는 독립적이다. projection 양수가 바깥 라인으로, 코끝 상하 양수는 위로만 이동한다. tip의 측면x 이동 항은 없으며 projection과 결합하지 않는다. 콧볼 폭·콧대 폭은 가로 효과이므로65°부터0으로 축소한다. UV 역변형의 위치는 현재 코끝 좌표에 따른다. 피부 마스크의 축/코 제외 영역/샘플 간격 uniform은 코 변형용 프레임과 분리해 탭 변경이 같은 촬영 보정 픽셀을 바꾸지 않도록 한다.

상담의 세부 조절/촬영 세부 보정은 native details를 사용한다. 접힘은 화면 표시만 바꾸며 값·canvas·연결·정지·동의 조건을 바꾸지 않는다. 옆모습 확인은 기존 필터 전환 함수를 사용하고 해당 탭에 포커스를 보낸다.

필터 첫 연결/장치 변경/연결 실패 후 재시도는 고정 숫자를 유지한다. 연결 취소/해제/track ended/새 상담/치명적 오류는 고정값을 비우고 상담 화면과 기본 숫자로 복원한다. mute는 영상만 비우고 필터값과 정지 의도를 유지한다. 필터에서는 버튼을 숨기는 것에 더해 App·Viewport의 캡처 진입점도 차단한다. 저장은 계속 상담의 엄격한 조건만 사용한다. 이 각도 확장은2D 시제품 기준이며 실제 측면/수술 후 구조 복원이 아니다. 모델이 실제 얼굴90°를 계속 검출한다는 보장도 아니다.
