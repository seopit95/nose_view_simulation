# 제품 범위와 인수 조건

관리 대상: 무엇을 만들고 무엇을 완료로 보는지. 구현 경계는 [architecture.md](architecture.md), 검증 방법은 [quality.md](quality.md)가 관리한다.

## 제품의 목적

의료진과 상담 담당자가 일반 USB 웹캠을 연결하고, 환자와 함께 코 윤곽의 시각적 변화를 비교하는 데 사용한다. 사용자의 사업 목표는 병원에 판매할 프로그램이다. 현재 구현 단계는 로컬에서 실행하는 0.9 시제품이며 판매 가능한 완제품 판정은 별도다.

일반 단안 RGB 웹캠을 전제로 한다. 깊이 센서, TrueDepth, LiDAR, 전용 촬영 장비를 필수로 추가하지 않는다. 현재 범위에서는 인터넷 없이 상담 흐름을 실행할 수 있어야 한다. 최초 개발 의존성 설치와 모델 준비는 이 조건에 포함되지 않는다.

## 현재 합의된 범위

| 항목 | 유지할 사용자 경험 / 인수 조건 |
|---|---|
| 앱 시작 | 한국어의 빈 카메라 연결 대기를 표시한다. 예시 기능/자산은 제공하지 않으며 자동으로 카메라를 켜지 않는다. |
| 웹캠 연결 | 장치를 선택하고 연결한다. 권한 거부·장치 없음·다른 앱 점유에 다음 행동을 안내한다. 마이크는 요청하지 않는다. |
| 추적 | 상담 모드는 단일 얼굴과 정면 조건을 만족한 프레임에서만 코 변형·저장을 허용한다. 필터는 유효한 측면 좌표를 허용하며 좌우 각도만으로 코 변형을 끄지 않는다. 조건 불량에도 촬영 톤과 안내는 유지한다. |
| 윤곽 조절 | 콧대 폭·옆모습 콧대·코끝 크기·코끝 상하·콧볼 폭·콧날개 상하·콧구멍 윗선·비주 상하를 상대 단위로 조절한다. 상담은 기본4개(콧대 폭·콧볼 폭·코끝 크기·코끝 상하), 접힌 세부4개. 설정창은4그룹. 선택 부위 가이드/개별0 초기화. 전체0은 무변형. 타입/필터/A·B·C/PNG는8개를 함께 처리한다. |
| 비교 | 원본·가상 보기·분할 비교, 비교 경계, 누르는 동안 원본, 거울 보기를 제공한다. |
| 촬영 보정 | 자연스럽게가 공장 기본. 없음/소프트/화사하게/따뜻하게/맑게와 피부 강도·밝기·색온도·대비·채도·색조·그림자·하이라이트 제공. 톤은 각도/얼굴 유무와 독립, 질감은 현재 단일 얼굴의 검증된 기하에 적용. 피부 강도·밝기는 바로 표시하고 나머지6개는 색감 세부 조절에 둔다. 동일 보정을 원본·가상·PNG에 표시한다. 비보정 확인은 보정 없음. |
| 기본 설정 | 현재 촬영 보정과 코 프리셋 수치 및 자동 적용 여부를 명시적으로 저장한다. 재실행·입력 변경·새 상담에 복원한다. 실패·손상은 안내하며 영상·환자·A/B/C는 보관하지 않는다. |
| 코 프리셋 | 이름 있는 여러 타입을 추가·편집·저장하고 상담 셀렉트로 즉시 적용한다. 기본 타입과 자동 적용(공장값 꺼짐)은 별도 지정한다. 이효리 코 타입은 실제 인물 측정값이 아닌 사용자 명명 시작값이며 기존 값은 유지된다. 촬영 보정 기본값은 타입 공통이다. |
| 실시간 필터 | 상단 탭에서 현재 코·촬영 수치를 고정해 전체 가상 영상을 본다. 탭 이동은 연결/정지 유지, 첫 연결/장치 변경도 고정값 유지. 보정 변경으로 상담 복귀. 유효한 좌우 측면에서는 방향에 맞게 코 라인 표현, 상하/기울임 한계에서는 감쇠, 추적 이탈에는 대기. 필터에서는 PNG 없음. |
| 정지 | 일시정지한 프레임에서도 유효한 윤곽 조절과 비교가 가능하다. 카메라 연결 유지 상태를 알린다. |
| A/B/C | 현재 상담의 조절값만 메모리에 저장·불러오기·갱신한다. 환자 이미지 보관함으로 확장하지 않는다. |
| PNG | 원본/가상 구분, 시뮬레이션 안내, 상대 조절값, 촬영 보정값, 웹캠 캡처 시각이 포함된 미리보기를 촬영 대상자 동의 확인 후 저장한다. |
| 연결 해제 | 트랙을 종료하고 이전 영상과 임시안을 비운다. 장치가 끊겨도 이전 얼굴이 남지 않아야 한다. |
| 새 상담 | 확인창을 거쳐 입력·영상·임시안을 정리하고 저장한 기본 수치로 복원한다. 저장된 파일 관리는 별도다. |
| 운영 환경 | macOS 일반 웹캠 우선. Windows 공통 코드 유지. 특정 OS 지원 완료는 해당 OS 패키지와 실물 장치 근거가 있어야 한다. |

사진의 절골 영역은 ‘콧대 폭’, 콧망울은 ‘코끝 크기’, 비공 내리기는 ‘콧구멍 윗선 → 아래로’로 표현한다. 사진 중앙에 적힌 콧망울은 이 앱에서 코끝으로 설명해 양옆 콧볼과 구분한다. 비공 내리기는 윗테두리를 내리는 시각 효과이며 구멍의 면적/노출량을 계측하는 기능이 아니다. 콧날개 상하와 비주 상하는 각각 내리기/올리기를 제공한다. 콧대 폭과 옆모습 콧대는 독립 조절한다. 옆모습 콧대는 정면에서 효과가 없음을 알리고 필터로 이동하는 옆모습 확인 버튼을 제공한다. 코끝 상하는 위/아래 방향이며 돌출·회전과 분리하고, 콧볼 폭은 측면으로 갈수록 축소한다. 세부 좌표가 불량하면 세부4항목을 차단하고 재검출 때 복구한다. 현재 프레임의3D 랜드마크를 사용하는2D 변형이며 정밀 콧구멍 분할·실제 높이·수술 구조 복원으로 설명하지 않는다. 얼굴 품질 판정은 모든 가림·모든 두 번째 얼굴을 찾아내는 기능이 아니다.

촬영 보정은 자연스럽고 밝게 보이는 상담 화면을 위한 기능이다. 피부 질감 완화에서 코·눈·눈썹·입술을 보호하며, 코 조절 이외의 얼굴 형태는 바꾸지 않는다. 기본값과 수치는 [설계](architecture.md)가 소유한다. 실제 피부·조명·웹캠에 대한 미관 평가는 합성 영상의 픽셀 시험으로 대체하지 않는다.

## 요청 없이 추가하지 않는 범위

- 실제 수술 후 결과 예측, 의료적 진단·권고, 보형물 선택, 조직 시뮬레이션, mm 계측.
- 측면 복원, 생성형 얼굴 합성, 개인별 3D 모델, TensorFlow 자체 학습 파이프라인.
- 계정·환자 DB·EMR·클라우드·원격 저장·얼굴 식별·자동 캡처·영상 녹화.
- 결제·구독·원격 업데이트·라이선스 서버·사용량 전송·원격 분석 SDK.
- 새 웹 서비스, 모바일 앱, 요청 범위를 넘는 화면 흐름 재설계, 운영체제 전용 재작성.

이 항목은 영구 금지가 아니다. 사용자가 요청하면 목적·데이터 흐름·인수 조건을 구체화하고 [결정 기록](decisions.md)에 변경 이유를 남긴다. 로드맵에 있다는 이유로 시작하지 않는다.

## 화면과 문구의 계약

- 상담 화면과 내보내기에 “가상 시뮬레이션이며, 실제 수술 결과와 다를 수 있습니다”라는 의미를 유지한다.
- 접은 세부 조절도 적용값을 유지한다. 코 세부값 중0이 아닌 개수를 표시해 숨은 효과를 알린다. 키보드로 펼치고 최소 창에서 모든 조절과 저장에 접근할 수 있어야 한다. 설명은 선택 부위 위주로, 진단 수치·촬영 도움말·고정값 목록은 펼쳐서 본다.
- 슬라이더 수치는 상대 단위다. 화면에 mm·확률·수술 성공률처럼 오해할 표기를 붙이지 않는다.
- 합성 이미지는 자동 검사에만 사용하고 앱 자산/기능으로 재도입하지 않는다. 실제 환자나 수술 전후 사례로 소개하지 않는다.
- 오류는 무엇이 중단됐고 어떻게 복구하는지 한국어로 설명한다. 코드·스택·내부 파일 경로는 제품 화면에 노출하지 않는다.
- 버튼 이름, 레이블, 키보드 조작, 포커스 표시를 유지한다. 자동 UI 검증은 역할과 텍스트로 요소를 찾는다.
- 화면 크기 변경, 기본 창 크기, 최소 창 크기에서 연결·조절·저장 버튼과 안내가 가려지지 않는지 확인한다.
- 0.5부터 밝은 쿨그레이/흰 카드/블루 주요 동작/라벤더 코 프리셋의 시각 언어를 사용한다. 둥근 모서리·충분한 글자와 여백을 일관되게 적용하며 색상만으로 선택·오류 상태를 표현하지 않는다.
- 버튼/탭/다이얼로그의 전환은 짧게 사용하고 OS 모션 줄이기를 따른다. 카메라 영상 픽셀과 종횡비는 UI 장식 때문에 변하지 않는다. overflow 영역 안의 키보드 초점과 선택+hover 조합에서도 식별 가능해야 한다.

## 작업마다 정의할 인수 조건

“추적 개선”, “자연스럽게”, “완벽하게”만으로 개발을 시작하지 않는다. 다음처럼 재현 가능한 관찰로 바꾼다.

| 모호한 요청 | 구체화할 조건의 예 |
|---|---|
| 카메라 안정화 | 연결 요청 뒤 취소하고 늦게 스트림이 도착해도 트랙이 종료되고 이전 영상이 나타나지 않는다. |
| 변형 안정화 | 동일 입력·동일 설정에서 코 영역 밖 픽셀은 그대로이며, 유효하지 않은 프레임에는 변형하지 않는다. |
| 성능 개선 | 동일 장치·입력·설정의 변경 전후 측정에서 처리 시간과 프레임 수를 비교하고 품질 저하 여부도 기록한다. |
| 저장 개선 | 동의 전 쓰기 불가, 취소 시 파일 없음, 실패 시 재시도 가능, 기존 파일 내용 유지가 확인된다. |

목표값이 정해지지 않은 성능·미관 항목은 측정 기준 또는 사용자 평가 기준부터 정한다. 기존 기획서의 목표 수치를 현재 성능이라고 인용하지 않는다.
