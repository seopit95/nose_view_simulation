# 작업 문서와 에이전트 프롬프트 양식

필요한 작업을 시작할 때만 이 양식을 복사한다. 아래 대괄호는 **양식의 입력란**이며 미완성 제품 요구사항이 아니다. 실제 작업 기록에서는 채우거나 `해당 없음: 이유`로 바꾼다.

## 개발 에이전트 시작 프롬프트

아래 내용을 복사해 현재 작업을 구체적으로 입력한다. 새 세션에서 전체 프로젝트 문서를 프롬프트에 붙일 필요는 없다.

```text
NoseView의 현재 프로젝트 루트에서 작업하라.
먼저 AGENTS.md와 docs/harness/status.md를 읽고,
요청에 필요한 소유 문서·구현·테스트만 추가로 읽어라.

이번 목표: [관찰 가능한 결과 한 문장]
허용 범위: [동작·파일 또는 모듈]
제외 범위: [이번에 하지 않을 기능]
완료 조건: [입력과 기대 결과, 필요한 검증]

작업 전 짧은 계획을 설명하라. 기존 변경과 승인 범위를 확인하고,
계획 → 필요한 재현/시험 → 최소 수정 → 실제 검증 → 결과 기록 순서로 진행하라.
불확실한 사실은 소스·공식 근거·실행 결과로 확인하고,
의도나 데이터 사용·승인 여부가 불분명한 부분만 사용자에게 물어라.
그 답이 필요하지 않은 작업은 계속 진행하라.

설계 불변 조건을 보존하고 범위 밖 개선을 끼워 넣지 마라.
삭제·결제·계정 변경·인증 및 되돌릴 수 없는 작업은 사전 확인 규칙을 따라라.
테스트 실패를 숨기거나 검증 기준을 낮추지 마라.
관련 필수 검증을 통과하기 전에는 완료라고 표시하지 마라.
실물 장치/다른 OS를 시험하지 않았다면 미검증으로 기록하라.

작업 기록에 근거와 다음 한 단계를 남겨 중단 후에도 이어갈 수 있게 하라.
마지막에는 결과·실행한 검증·남은 제한을 짧게 보고하라.
```

## 작업 기록 양식

저장 위치: `docs/harness/tasks/YYYY-MM-DD-topic.md`. 생성 후 [status.md](status.md)의 진행 중 작업에 연결한다. 완료 후 파일 이동/삭제 대신 상태와 완료일을 갱신한다. 이 양식에 적힌 상대 경로는 **이 양식 기준**이며, tasks에 복사한 링크는 새 위치에 맞게 고친다.

```markdown

- 상태: active / blocked / completed 중 하나
```

## 이어서 작업할 때

진행 중인 작업 기록과 실제 파일·대상을 대조한다. 이전 실행 결과를 새 실행처럼 기록하지 않는다. 진행 중 작업이 없으면 현재 사용자 요청을 기준으로 새 범위를 정한다. 현황의 후보 목록을 자동으로 전부 수행하지 않는다.
