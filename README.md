# NoseView 0.9.0

일반 USB 웹캠으로 코 윤곽을 실시간 비교하는 **상담용 개발 시제품**입니다. Electron · React · TypeScript · MediaPipe Face Landmarker · Three.js로 만들었습니다. TensorFlow를 별도로 설치할 필요는 없습니다.

0.9.0은 상담 용어와 조절 방향을 맞추고 기본 코4개·촬영2개만 우선 보여줍니다. **세부 조절**과 **색감 세부 조절**을 펼치면 나머지 항목을 조절할 수 있습니다. 접어도 값과 효과가 유지되고 코 세부 항목의 적용 개수를 표시합니다. 코끝 상하의 측면 돌출 결합을 없애고 콧구멍 윗선 조절의 아래쪽 경계를 보호했습니다.

코 조절은 부위별8개 항목입니다. 선택 부위 가이드와 개별 초기화를 제공하며, 여러 코 타입·기본 설정·실시간 필터·A/B/C·PNG에 모두 반영됩니다. 예시 기능은 제공하지 않습니다.

0.8.1은 웹캠 연결 중 안내와 첫 영상 수신 시간 초과 안내를 수정했습니다. 장치 이름이 보여도 실제 영상 전송이 성공한 것은 아닙니다. USB 전송 오류로 첫 영상이 오지 않으면 USB 재연결·직접 연결·다른 앱 종료 후 재시도 방법을 안내합니다. 이 안내 개선이 케이블·허브·장치 오류 자체를 복구했다는 뜻은 아닙니다.

## 바로 사용하기

Mac용 ZIP을 풀고 `NoseView.app`을 실행하세요. 빈 카메라 연결 대기 화면으로 시작합니다. 앱 실행에는 Node.js나 인터넷 연결이 필요하지 않습니다. 제공한 Mac 패키지는 Apple Silicon(arm64)용입니다.

1. 왼쪽에서 연결할 웹캠을 선택하고 **웹캠 연결**을 누릅니다. 첫 연결에서는 운영체제 카메라 권한을 허용합니다.
2. 얼굴 한 명이 화면에 온전히 보이도록 정면을 맞춥니다. 추적 조건을 만족하면 코 조절 슬라이더가 켜집니다. 촬영 톤은 그 전부터 적용됩니다.
3. **콧대 폭 / 콧볼 폭 / 코끝 크기 / 코끝 상하**를 먼저 조절합니다. **세부 조절**에서 **콧날개 상하 / 콧구멍 윗선 / 비주 상하 / 옆모습 콧대**를 조절합니다. 선택한 부위를 영상에 표시하며 옆의 **0** 버튼으로 해당 항목만 초기화합니다. 값은 상대 단위이며 실제 길이나 수술량이 아닙니다. **비공 내리기**는 **콧구멍 윗선 → 아래로**, **콧날개 올리기**는 **콧날개 상하 → 위로**입니다.
4. **비교 / 가상 보기 / 원본** 탭을 바꾸거나 비교 경계를 끕니다. **눌러서 원본**은 누르고 있는 동안 원본을 보여줍니다.
5. A/B/C에 설정을 담고 다시 불러옵니다. **갱신**은 해당 안을 현재 조절값으로 바꿉니다.
6. **비교 이미지 저장**에서 안내 문구가 포함된 결과를 확인하고 저장 동의를 체크한 뒤 PNG를 저장합니다. 같은 이름의 기존 파일은 덮어쓰지 않습니다.
7. **새 상담**은 확인 후 카메라를 끄고 화면과 임시안을 비웁니다. 이미 내보낸 PNG는 별도로 관리합니다.

왼쪽 **피부 · 화면 톤**에서 **보정 없음 / 자연스럽게 / 소프트 / 화사하게 / 따뜻하게 / 맑게**를 선택합니다. 피부 강도와 화면 밝기는 바로 조절하고, 색온도 등 나머지6개는 **색감 세부 조절**을 펼칩니다. 피부 강도는 0~100, 밝기·색온도·대비·채도·색조·그림자·하이라이트는 각각 -100~100입니다. 화면 톤은 얼굴 각도나 얼굴 검출 여부에 관계없이 적용됩니다. 피부 질감은 현재 얼굴 위치를 확인할 수 있을 때 이마·볼·턱 안쪽에 적용하며 코·눈·눈썹·입술을 보호합니다. 원본·가상·PNG에 같은 보정을 적용하므로 필터 없는 영상은 **보정 없음**으로 확인하세요.

마음에 드는 보정은 상단 **기본 설정 → 기본 설정 저장**으로 보관합니다. 다음 실행·웹캠 연결·새 상담부터 저장한 수치를 불러옵니다. 상담 중 조절은 자동 저장하지 않습니다. **내 기본 보정 불러오기**로 저장값을 다시 적용할 수 있습니다. 얼굴 영상과 A/B/C는 기본 설정에 포함하지 않습니다.

오른쪽 **코 타입** 선택 상자에서 저장한 타입을 고르면 즉시 적용합니다. 수동 조절 후 같은 타입으로 돌아가려면 **선택한 타입 적용**을 누르세요. **프리셋 설정 → 타입 추가**에서 이름과8개 코 조절값을 편집한 뒤 **기본 설정 저장**을 누르면 여러 타입을 보관할 수 있습니다(최대50개, 이름32자). 새 타입은 현재 상담 수치로 시작하며 **현재 코 조절값 가져오기**로 다시 복사할 수 있습니다. 이름이 비거나 중복되면 저장 전에 안내합니다. 취소하면 편집 내용은 반영되지 않습니다.

설정창의 **편집할 코 타입**과 다음 상담의 **기본 코 타입**은 따로 선택합니다. **새 상담에 코 프리셋 자동 적용**은 기본 꺼짐이며, 켜면 다음 실행·연결·새 상담부터 지정한 기본 타입을 적용합니다. 촬영 보정 기본값은 모든 코 타입에 공통입니다. 기존 **이효리 코 타입**도 유지되며 이름과 수치를 바꿀 수 있습니다. 제공 시작값은 콧볼 폭 −18 / 콧대 폭 −10 / 옆모습 콧대 +10 / 코끝 상하 +8 / 나머지0이며 실제 인물의 측정·재현값이 아닌 사용자 프리셋입니다. 이전 설정은 기존 숫자를 보존하고 옆모습 콧대에 기존 콧대 값의 부호를 반대로 넣으며, 새 세부 항목은0으로 시작합니다. 부위 변형 방식이 개선되었으므로 이전 앱과 픽셀이 완전히 같다는 뜻은 아닙니다.

**옆모습 콧대**는 정면에서 변화가 보이지 않습니다. 수치를 정한 뒤 **옆모습 확인**으로 필터에 들어가 고개를 돌려 확인하세요.

상단 **실시간 필터**를 누르면 현재 코 윤곽과 촬영 보정값이 고정되고 비교선 없는 큰 영상으로 표시됩니다. 탭을 오가도 웹캠 연결과 일시정지 상태는 유지됩니다. **보정 변경**을 눌러 상담 화면에서 다시 조절한 뒤 필터 탭에 들어가세요. 필터 안에서 처음 연결하거나 장치를 바꾸어도 고정 수치는 유지되며, 연결 해제·연결 취소·새 상담·치명적 오류에서는 해제됩니다. 필터 모드에서는 PNG를 저장하지 않습니다.

카메라의 **일시정지**는 화면 처리를 멈추고 촬영 연결은 유지합니다. 연결까지 끄려면 **웹캠 연결 해제** 또는 **새 상담**을 사용하세요. 앱이 배경으로 숨겨지면 처리를 일시정지하며 다시 재생 버튼으로 재개합니다. 입력을 변경하면 임시 비교안은 비우고 조절값은 저장한 기본값으로 복원합니다. 실시간 필터에서의 첫 연결·장치 변경은 고정한 수치를 유지하는 예외입니다.

## 개발 환경에서 실행

Node.js 22.12 이상과 npm이 필요합니다. Windows와 macOS에서 아래 명령을 **소스 폴더 안**에서 실행합니다. 최초 의존성 설치에는 인터넷이 필요합니다.

```sh
npm ci
npm start
```

개발 화면: `npm run dev` → 표시된 로컬 주소를 Chrome/Edge에서 엽니다. Electron 전용 저장·네트워크·권한 정책 검증은 `npm start`로 해야 합니다. Worker 코드를 고치면 개발 서버를 다시 시작합니다.

```sh
npm test         # 품질 조건, 변형 경계, 프레임 처리 회귀 테스트
npm run build    # 모델 체크섬 검증 + TypeScript 검사 + Worker/화면 빌드
npm run test:e2e # 실제 Electron/MediaPipe/가상 카메라 통합 검증
npm run make    # 현재 운영체제/아키텍처용 앱과 ZIP 생성
npm run verify  # 단위·문서 → 새 패키지 → 전체 통합/권한 → audit, 실패 시 중단
```

`npm run test:e2e` 실행 전에는 `npm run build`를 먼저 실행합니다. E2E는 Electron 창을 열며 테스트 결과를 `qa/`에 만듭니다. 일반 통합 검사는 합성 인물의 가상 MediaStream과 실제 MediaPipe를 사용합니다. 별도의 `profile-filter.mjs`는 알려진 회전 좌표를 주입해 GPU와 상태 경계를 검증하며 모델의 실제 측면 검출 성능을 검증하지 않습니다. 시스템 카메라는 활성화하지 않습니다.

패키지 검증은 `node scripts/run-packaged-test.mjs`로 실행합니다. 현재 프로젝트의 소스와 앱 해시를 대조한 뒤 기본 통합·상태 경합·촬영 보정·기본 설정·여러 코 타입·실시간 필터·UI 배치·가상 장치 권한 검사를 순서대로 수행합니다. 폴더를 복사했거나 소스를 변경했다면 `npm run make`로 먼저 다시 만드세요. 테스트 결과는 시작 상태와 실행 대상을 기록하므로 과거 성공 보고서를 현재 결과로 간주하지 않습니다.

Windows 배포 ZIP은 **Windows x64 PC에서** `npm ci` → `npm run make`로 만듭니다. Mac Intel용은 해당 환경에서 빌드·검증하세요. Windows 및 Intel Mac의 실제 장치 호환성은 이번 Mac arm64 검증에 포함되지 않았습니다.

## 구현 구조

- `desktop/main.cjs`: 로컬 app:// 프로토콜, 카메라 권한, 외부 연결 차단, 검증된 PNG 저장 IPC.
- `src/App.tsx`: 카메라 수명 관리, 상태 전환, 한국어 상담 화면, A/B/C 임시 설정.
- `src/tracking/face.worker.ts`: MediaPipe를 classic Worker에서 실행. GPU 초기화 실패 시 CPU를 시도합니다.
- `src/tracking/pipeline.ts`: 최대 한 프레임만 처리. 동일 프레임의 영상·랜드마크를 돌려받고 이전 입력 결과는 폐기합니다.
- `src/core/geometry.ts`: 얼굴 수, 자세, 프레임 경계 및 크기 조건. 상대적인 코 영역 계산.
- `src/core/adjustments.ts`:8개 코 조절값과 표시명·방향·그룹·범위의 공통 정의.
- `src/core/beauty.ts`: 촬영 보정 기본값, 범위 제한, 얼굴 안쪽 피부 영역과 눈·눈썹·입술 보호 영역 계산.
- `src/components/Viewport.tsx`: Three.js 국소 역방향 UV 변형, 촬영 보정, 원본 비교, 워터마크 포함 내보내기.
- `public/assets/`: 검증된 모델과 앱 아이콘. WASM은 빌드 시 패키지에서 복사합니다. 합성 인물은 `tests/fixtures/`에만 있으며 앱/ZIP에는 포함하지 않습니다.
- `tests/`: 단위 및 실제 모델 통합 검증. [현재 상태](docs/harness/status.md)에서 결과와 미검증 항목을 확인하세요.

카메라는 1920×1080 / 30 fps를 선호하는 제약으로 요청합니다. 실제 선택 해상도는 장치에 따라 달라지며 화면 아래 **촬영 상태**를 펼치면 표시 크기와 처리 수치를 보여줍니다. 표시 프레임의 긴 변은 최대 1920픽셀로 유지하고 작은 입력을 확대하지 않습니다. MediaPipe는 같은 프레임의 긴 변 최대 960픽셀 복사본을 사용합니다. 추적에 피부 필터를 적용하지 않습니다. 표시 fps와 “프레임 처리 ms”는 처리량·프레임 취득부터 결과 수신까지의 시간입니다. 센서 노출부터 모니터 표시까지의 지연을 측정한 수치가 아닙니다.

## 데이터 처리와 배포 상태

모델과 WASM은 앱에 포함되며 앱 런타임에서 외부 네트워크 요청을 차단합니다. 영상/환자명/상담 기록 DB를 만들지 않습니다. A/B/C는 메모리의 조절값만 저장합니다. 내보낸 PNG에는 얼굴이 포함되며 **암호화된 환자 기록 저장소가 아닙니다**. 저장 파일은 사용자가 선택한 위치에서 별도로 관리해야 합니다. Electron/운영체제의 일반 앱 캐시·권한 정보는 생성될 수 있습니다.

패키지는 개발용이며 Developer ID 서명·Apple 공증·Windows 코드 서명은 설정하지 않았습니다. 외부 병원에 정식 배포할 설치 프로그램과 업데이트/라이선스 관리 기능은 아직 없습니다. macOS에서 확인되지 않은 개발자 안내가 나오면 제공받은 코드와 출처를 확인한 후 운영체제의 정상 승인 절차를 사용하세요. 전역 보안 설정을 끄지 마세요.

## 현재 한계와 다음 개발

이 시제품은 **2D 영상의 코 윤곽을 바꾸는 시각적 도구**입니다. 실제 코 높이, 연골·뼈·피부 조직, 보형물, 수술 방법 또는 수술 결과를 예측하지 않습니다. 측면·가려진 영역을 재구성하는 3D 시뮬레이터가 아닙니다.

상담 모드는 정면에서 대략 ±20° 조건을 유지합니다. 실시간 필터는 유효한 현재 얼굴 좌표가 있으면 좌우90°까지 각도만으로 코 보정을 끄지 않습니다. 콧대 폭과 옆모습 콧대는 독립적으로 조절하며 코끝 상하는 얼굴의 위아래 축으로만 이동하며 측면 돌출이나 코끝 회전을 재현하지 않습니다. 콧볼 폭 효과와 가려진 쪽의 세부 보정은 측면으로 갈수록 작아집니다. 상하20~30°·기울임30~50°에서는 보정을 줄입니다. 얼굴 검출 자체가 끊기거나 좌표가 불량하면 코 변형은 멈추고 화면 톤은 유지합니다. 세부 경계 좌표를 확인할 수 없으면 코끝 크기·콧날개·콧구멍·비주 조절은 잠시 차단합니다. 부위는 랜드마크 기반 영역이며 콧구멍 픽셀의 정밀 분할이 아닙니다. 실제 웹캠의 완전 측면 검출·부위 위치·미관은 사용자 시험이 필요합니다. 합성 좌표90° 통과는 실제 얼굴90° 인식 성공을 뜻하지 않습니다. 손·마스크 가림, 강한 그림자, 빠른 움직임, 다양한 얼굴 형태와 흔들림은 추가 검증 대상입니다.

피부 보정은 얼굴 좌표 기반 영역을 사용하며 머리카락·손을 정밀 분할하는 모델은 아닙니다. 조명이 부족하거나 카메라 원본이 흐리면 필터로 사라진 디테일을 복원할 수 없습니다. 실제 웹캠에서 밝기·질감·색감과 처리 속도 확인이 필요합니다.
